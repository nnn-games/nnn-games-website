# 정기 점검 절차

이 스킬은 **진단만** 한다. 발견 사항의 조치는 아래 표의 스킬로 넘긴다.

## 1. 실행
```
npm run audit                     # 보고서 → exports/audit/audit-YYYY-MM-DD.md (+ .json, latest.md)
npm run audit -- --skip-links     # 오프라인일 때
npm run audit -- --max-age-days 7 # 지표 나이 기준 변경 (기본 3일)
```
- CI 는 매주 월요일 10:00 KST 에 `Site audit` 워크플로로 같은 점검을 돌려 `audit` 라벨 이슈를 만들거나 갱신한다. 수동: `gh workflow run audit.yml`.
- 사용자가 이슈를 가리키며 요청하면 이슈 본문의 보고서를 읽고 아래 절차로 조치한다.

## 2. 보고서 읽는 법
- 🔴 오류: 바로 조치. 🟡 경고: 검토 후 조치 여부 결정. ⚪ 정보: 참고.
- 같은 항목이 매주 반복되면 규칙 자체가 잘못됐을 수 있다. 사용자에게 기준 조정을 제안한다.

## 3. 발견 → 조치 매핑

| 구분 | 발견 | 조치 |
| --- | --- | --- |
| 검증 | check:* 실패 | 메시지의 파일을 고친다. i18n 은 `/update-project` 또는 `/update-deck`, 데이터 규칙은 `/update-project` |
| 지표 신선도 | 지표가 기준일보다 오래됨 | Actions 의 `Update metrics` 실행 이력을 확인. 스케줄이 꺼졌으면(60일 미활동) Actions 탭에서 다시 켠다. 즉시 갱신은 `/refresh-metrics` |
| 지표 신선도 | active 인데 visits 0 | universeId 오타 또는 게임 비공개. 사용자에게 확인 후 `/update-project` 또는 `/retire-project` |
| 외부 링크 | 404/타임아웃 | `/update-project`로 링크 교체 또는 비움. 덱의 링크는 `/update-deck` |
| 외부 링크 | 403/405/429 | 봇 차단일 수 있으므로 브라우저로 직접 확인. 정상이면 무시 |
| 번역 누락 의심 | ko 문구가 en/ja 에 그대로 | 번역을 채운다. 사이트는 `site/js/i18n.js`, 덱은 `slides.js`. 고유명사(브랜드명)면 무시 |
| 덱 수치 인용 | 데이터와 15% 이상 차이 | `/update-deck`으로 수치와 갱신일 문구를 갱신. 외부 통계(플랫폼 전체 수치 등)면 무시 |
| 에셋 위생 | 2MB 초과 | 압축 후 교체(가로 1200px 이하). 이름을 바꾸면 참조도 함께 |
| 에셋 위생 | 참조 없음 | 정리 후보 목록을 사용자에게 보여주고 승인 후 삭제. 덱 `img/` 는 원고용일 수 있으니 decks 역할과 확인 |

## 4. 조치 후
- 조치는 별도 브랜치(`site/audit-YYMMDD` 또는 `decks/audit-YYMMDD`)에서 하고 `npm run check`를 통과시킨다.
- 조치 완료 항목을 이슈에 코멘트로 남기고, 모두 처리되면 이슈를 닫는다.
