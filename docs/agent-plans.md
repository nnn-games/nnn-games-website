# 여러 단계 작업의 실행 계획

화면·데이터·덱 등 여러 파일의 변경이 이어지거나 세션을 넘겨 작업할 때 사용합니다. 단순 문구 수정에는 필요하지 않습니다. 계획 파일 자체가 승인 절차를 추가하지 않습니다.

작업 시작 시 `tmp/plans/<작업명>.md`에 아래 내용을 기록하고 진행에 맞춰 갱신합니다. 장기 보존할 결정과 최종 결과는 관련 `docs/site/`, `docs/projects/`, `docs/decks/` 및 개발 로드맵에 반영합니다.

```markdown
# 작업명

## 목표와 완료 조건

사용자가 요청한 결과, 대상 화면·청중·언어, 완료를 확인할 동작.

## 확인한 맥락

실제 관련 파일, 참고 자료, 재현 조건, 유지할 URL·데이터·공통 동작.

## 진행 상태

- [ ] 구현 또는 원고 작성
- [ ] 정적 검사
- [ ] 관련 브라우저 동작·화면 증거 확인
- [ ] 문서 갱신·결과 보고

## 결정과 남은 정보

확인된 사실, 선택 이유, 사용한 가정, 사용자 입력이 필요한 정보.

## 검증 증거

실행 명령, 통과·실패 결과, 보고서와 스크린샷 위치, 남은 한계.
```

컨텍스트가 바뀌어도 이 파일과 Git diff로 진행 상태를 복구합니다. 새 계획을 시작하느라 완료된 작업을 반복하지 않습니다. 이 형식은 공식 가이드의 선택적 장기 작업 계획 방식을 이 저장소에 맞게 간소화한 것입니다. [OpenAI Best practices: Plan first](https://learn.chatgpt.com/guides/best-practices#plan-first-for-difficult-tasks).
