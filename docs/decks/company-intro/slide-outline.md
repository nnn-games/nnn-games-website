# 신규 회사 소개 슬라이드 구성안 v1

작성일: 2026-10-01  
대상: 협력사·브랜드/IP 파트너를 만나는 일반 회사 소개  
권장 분량: 본편 13장 + 선택 부록 4장, 본편 약 10~15분을 가정  
검토 근거: [보관 덱 비교 검토](comparison.md)

이 문서는 신규 덱의 구성안과 제작 기준입니다. 2026-10-01 본편 13장·부록 4장을 KO/EN/JA로 구현했습니다. 실제 인용 근거는 [제작 출처](sources.md)에 기록합니다. 새 회사 소개의 중심 메시지는 **“Roblox 게임 개발부터 UGC 제작, 출시 이후 운영까지 연결하는 스튜디오”**로 제안합니다. 자체 게임을 통해 쌓은 경험과 파트너에게 제공할 수 있는 제작·운영 역량을 보여주고, 현재 개발 프로젝트와 협업 논의로 이어갑니다.

본문 원고는 한국어 기준으로 정리하고 KO/EN/JA로 작성했습니다. 회사·개인 경력과 역사적 성과는 기존 덱에 기재된 근거이며 최신 사실 확인이 필요한 항목을 아래에 표시했습니다.

슬라이드 타이틀은 두 단어 이내의 개념명으로 통일합니다. 전체 17장의 서브타이틀·도입 문구는 화면에서 제거하고 [발표 메모](speaker-notes.md)에 보관합니다. 아래의 주장은 구두 설명 기준이며 화면에는 제목·실제 사례·이미지·수치·본문 자료를 표시합니다.

## 2. 슬라이드별 구성

### 01 회사소개

- **주장:** Roblox 게임 개발·UGC 제작·라이브 운영을 한 흐름으로 수행하는 스튜디오.
- **본문:** 회사명, 게임 개발·UGC 제작·라이브 운영 역량 항목, 발표 기준 월. 중심 메시지는 구두로 설명.
- **시각 자료:** 현재 운영 게임을 중심으로 한 대표 이미지 2~4장. 개발 중 프로젝트 이미지를 쓰면 상태를 표시.
- **근거·자료:** 기존 두 덱 cover, [현행 프로젝트 메타][projects], 홈페이지 연락처.
- **보완:** 현재 표기할 대표·이메일·주소 확인. 기존 덱의 대표 이메일은 nnnceo@triplengames.com, 홈페이지 일반 문의는 developer@triplengames.com으로 용도를 정리. 주소는 본편 마지막 장에 모아 표지를 간결하게 구성.

### 02 주요지표

- **주장:** 현재 운영 프로젝트와 커뮤니티를 가진 제작·운영 조직.
- **본문:** 운영 게임 **6개**, 누적 방문 **14,008,163회 → 1,400만+**, 집계 대상 커뮤니티 가입 수 **208,979 → 20.8만+**. 하단에 게임 개발·라이브 운영·UGC 3대 역량을 한 줄씩 설명.
- **시각 자료:** 숫자 카드 3개와 간단한 개발→출시→운영→개선 흐름.
- **근거·자료:** [projects.summary.hero][projects], [communities.totals.heroSubscriberCount][communities]. 기준일 2026-10-01 14:57 KST.
- **표기:** 누적 방문은 방문 횟수. 커뮤니티 숫자는 7개 그룹 가입 수 합계이며 중복 제거 인원이 아님. 숫자 옆에 단위·범위를 명시.

### 03 운영게임

- **주장:** 서로 다른 장르의 게임을 실제로 개발·운영한 경험.
- **본문:** Tower Flood Race, Tomato Splatter Simulator, [Free UGC] AFK or arcade game, FREE UGC RNG, Korean Spa, Fruit Battles. 각각 이름·장르 또는 핵심 재미·누적 방문을 표시.
- **시각 자료:** 2열×3행, 원본 비율의 전체 포스터와 설명을 나란히 배치한 프로젝트 카드. 현재 저장소의 이미지와 수치를 사용하고 오래된 NEW 배지는 제거.
- **근거·자료:** [projects.all의 active 6종][projects], 각 `site/js/project-details/` 콘텐츠.
- **보완:** 이전 덱에 없던 Korean Spa·Fruit Battles 포함. 방문 수 내림차순을 기본으로 하되 다음 사례 장에 연결되는 대표작을 분명히 표시. 지표·기준일은 모든 카드에서 동일하게 사용.

### 04 게임설계

- **주장:** 장르별 핵심 재미와 반복 플레이 흐름을 구체적으로 설계.
- **본문:** TFR은 상승하는 물·경쟁·보상·재도전, Tomato Splatter Simulator는 타격·자원 획득·성장·다음 목표. 각 사례는 핵심 재미 한 줄과 3~4단계 루프로 정리.
- **시각 자료:** 게임별 실제 장면 1장과 플레이 루프. 03의 방문 수를 반복하기보다 설계 차이를 보여줌.
- **근거·자료:** 두 덱의 case, 현재 프로젝트 상세 설명.
- **보완:** 최신 게임 화면 확보. 리텐션·수익 개선율은 별도 기록이 있을 때만 추가.

### 05 UGC 보상

- **주장:** 무료·한정 UGC를 게임 안의 수집과 보상 목표로 연결.
- **본문:** AFK or arcade game의 플레이·코인·교환, FREE UGC RNG의 수집·성장·한정 보상. 각 게임의 현재 구현을 기준으로 흐름을 정리.
- **시각 자료:** 두 게임의 화면과 플레이→재화/수집→UGC 보상 흐름. 실제 제작 UGC 일부를 함께 배치.
- **근거·자료:** 두 덱의 ugc, 현재 AFK·RNG 상세 콘텐츠.
- **보완:** 구형 Merge 설명이 현재 기능과 맞는지 확인. 06에서는 제작물, 이 장에서는 게임과 보상의 연결을 보여줌.

### 06 UGC 제작

- **주장:** 아바타 아이템을 제작하고 게임·판매 흐름에 연결하는 역량.
- **본문:** 대표 제작물, 제작 가능한 부위·소재·애니메이션 범위, 게임 연동 과정. NNN UGC는 **UGC 제작 프로젝트**로 별도 소개.
- **시각 자료:** 최신 대표 UGC 6~8개와 아바타 착용 예시. 기존 썸네일 12개 전체는 필요하면 부록으로 이동.
- **근거·자료:** 공통 ugcworks, [NNN UGC 현재 설명][nnn-ugc], `decks/company/assets/ugc-*.png` 등 기존 자산.
- **보완:** 제작물 공개 가능 범위와 큰 이미지 확보. NNN UGC 프로젝트의 제작 상태와 같은 이름의 커뮤니티 지표를 구분. 매출·판매량·납품 단가는 근거 없이 제시하지 않음.

### 07 라이브 운영

- **주장:** 출시 이후 이벤트·보상·콘텐츠 개선을 이어가는 운영 경험.
- **본문:** 기존 Top 100 Challenge·Golden Ducky 사례 중 현재 설명 가능한 대표 이벤트 1~2개. 목표→참여 방식→보상→운영 후 개선 흐름으로 정리.
- **시각 자료:** 실제 이벤트 화면/배너와 운영 사이클. 퀘스트·랭킹·한정 UGC를 짧은 항목으로 연결.
- **근거·자료:** nnn liveops, 공통 게임 사례, 보관된 이벤트 이미지.
- **보완:** 이벤트 시행 기간과 현재 운영 여부 확인. 과거 사례에는 시행 기간을 쓰고 현재 상시 운영으로 오해할 문구는 피함.

### 08 보유기술

- **주장:** 반복 업무를 지원하는 시스템을 직접 구축한 경험.
- **본문:** UGC 자동 지급·관리, 기간/주기별 이벤트 운영, 게임 간 크로스 프로모션. 시스템별 사용 목적과 실제 적용 범위를 한 줄씩 설명.
- **시각 자료:** 관리자 화면 1개, 이벤트 화면 1개, 유입 연계 화면 1개. 각 화면이 어떤 운영 작업을 지원하는지 캡션을 붙임.
- **근거·자료:** company tech와 `ugc-admin.jpg`, `ugc-operation*.jpg`, `cross-promotion.jpg`.
- **보완:** 현재 사용 중인 시스템과 화면 확인. 기존 “운영인력 없이 상시 운영” 표현은 실제 자동화 범위로 구체화. 인력 절감·안정성·보안 효과는 측정값 또는 설명 가능한 구현 범위에 맞춰 기술.

### 11 협업사례

- **주장:** 파트너와 협업하고 외부 서비스를 게임형 체험에 연동한 경험.
- **본문:** JR EAST × NAVER Z Get Train, 야마노테선 소재 체험, JRE WALLET 연동 및 이벤트 개발·운영에서 담당한 역할.
- **시각 자료:** 기존 Get Train 이미지 중 대표 2장과 담당 범위. **ZEPETO 프로젝트**와 해당 수행 기간을 명시.
- **근거·자료:** 두 덱 global. 기존 기재 기간 2024.09~2025.12, 기재 성과 2.5M 방문·600K Peak WAU.
- **보완:** 과거 성과의 원본 자료와 측정 기간, 담당 범위 확인. 성과 확인 전에는 역할·화면 중심으로 제작하며, 이 수치를 현재 Roblox 합계에 더하지 않음.

### 12 IP 전략

- **주장:** 기존 게임·UGC·커뮤니티 운영 경험을 바탕으로 브랜드 목적에 맞는 체험을 제안할 수 있음.
- **본문:** 친숙한 플레이로 IP 접점 만들기→UGC와 참여 목표 연결→커뮤니티 형성→홍보/콘텐츠/이벤트로 확장하는 **제안 접근법**. 전체 3~4단계로 압축.

- **근거·자료:** company kungya-entry/community/expansion, [현재 NNN UGC 그룹 지표][communities].

## 4. 수치와 자료를 확정하는 기준

- 비교 검토 당시 스냅샷은 [비교 검토](comparison.md)에 보존했습니다. 제작 시 `npm run update:metrics`를 실행했고, 새 스냅샷·출처·기준일은 [제작 출처](sources.md)에 기록했습니다.
- 운영 프로젝트 수·방문 합계는 `summary.hero`, 커뮤니티 합계는 `totals.heroSubscriberCount`의 집계 대상을 따릅니다. 개발 게임과 NNN UGC 제작 프로젝트는 운영 게임 수에 더하지 않습니다.
- 방문·커뮤니티 축약 숫자는 내림 표기합니다. 정확한 수치는 A2에 기록합니다. 좋아요 비율을 쓰면 별도 기준일과 반올림 규칙을 기록합니다.
- Peak CCU, Get Train 과거 성과, 1개월 커뮤니티 성장, 판매·리텐션 성과는 해당 기간의 자료가 확보된 항목만 사용합니다.
- 출시 예정 월, 공개 가능한 실제 게임 화면·UGC 제작물을 확인한 뒤 본문을 확정합니다. 이미지에는 실제 화면·개발 화면·콘셉트의 성격을 표시합니다. 팀소개는 사용자 요청에 따라 nnn 원본 구성을 확정했습니다.
